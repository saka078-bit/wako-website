# 経費精算アプリ ─ 叩き台（v0.1）

和光建設向け経費精算アプリの提案と、動くプロトタイプです。
`keihi/index.html` をブラウザで開けばそのまま動きます（インストール不要・単一HTML）。

---

## 1. 何を解決するか

解体・建設の現場では、経費が「現場ごと・その場・立替」で発生します。

| よくある困りごと | このアプリでの解き方 |
| --- | --- |
| 領収書が財布や車の中に溜まり、月末にまとめて格闘 | その場でスマホ撮影 → 30秒で申請完了 |
| どの現場の経費か後から分からない | 入力時に現場（案件）を必ず紐づけ |
| 誰にいくら立替が残っているか不明 | 「未精算（立替残）」を常時表示 |
| 承認がLINE・口頭で流れる | 申請 → 承認 → 精算済 のステータスで記録が残る |
| 会計へ渡すのに手入力し直し | CSV書き出し（税抜・消費税・税区分つき） |

## 2. プロトタイプでできること

- **入力**：金額 → 費目タップ → 日付・現場・支払方法 → 領収書撮影 → 申請
  - 領収書は端末側で自動縮小（長辺1000px / JPEG）してから保存
  - 1万円以上で領収書未添付なら注意表示
  - 下書き保存 → あとから申請、もOK
- **一覧**：月／ステータス／社員／現場で絞り込み、合計を即時表示。タップで詳細・編集・削除
- **承認**：ヘッダーの「申請する人／承認する人」を切り替えると承認・差戻し（理由つき）・精算済が操作可能。承認済をまとめて精算済にする一括処理つき
- **集計**：未精算（立替残）／当月合計／承認待ち件数／消費税額の4指標＋費目別・現場別・申請者別のグラフ
- **書き出し**：CSV（Excel向けBOM付き、税抜・消費税を自動計算）／JSONバックアップ・復元
- **設定**：社員・現場・費目のマスタ登録。サンプルデータ投入で挙動を試せます

初期の費目：交通費／高速・ETC／駐車場／燃料費／資材・工具／消耗品／産廃処分費／接待交際費／その他（自由に追加・削除可）

## 3. 割り切っている点（プロトタイプの制約）

- データは**開いた端末のブラウザ内（localStorage）にのみ**保存。社員間で共有されません
- 容量の目安は約5MB。領収書写真は1枚あたり約100〜200KB
- ログイン・権限制御なし（役割はボタン切り替えのみ）
- 会計ソフト連携、OCR（金額自動読み取り）、通知は未実装

→ **社内で実運用するなら第2フェーズが必要です。**

## 4. 進め方の案

| フェーズ | 内容 | 期間の目安 |
| --- | --- | --- |
| **1. 叩き台**（今ここ） | 単一HTML／端末内保存。画面と項目を実物で確認 | 完了 |
| **2. 共有化** | データをクラウドへ。社員ログイン、承認通知、複数端末で同じデータ | 2〜3週間 |
| **3. 現場運用** | スマホのホーム画面追加（PWA）、オフライン入力、写真の安全な保管 | +1〜2週間 |
| **4. 効率化** | 領収書OCRで金額・日付を自動入力、会計ソフト向け仕訳CSV、月次締め | 応相談 |

フェーズ2の技術候補（いずれもサーバー管理不要・低コスト）：

- **Googleスプレッドシート + Apps Script** — 経理が普段の表計算のまま扱える。追加費用ほぼゼロ
- **Supabase** — ログイン・画像保管・権限管理が最初から揃う。無料枠内で開始可能
- **kintone等のSaaS** — 開発不要だが月額が人数分かかる

現状のサイトが静的HTMLで運用されていることを踏まえると、**まずはスプレッドシート連携が相性が良い**と考えています。

## 5. 決めていただきたいこと

1. 使う人は何名くらいか（申請者／承認者）
2. 承認は1段階でよいか（社長承認のみ／現場監督→社長 など）
3. 立替の精算タイミング（給与と一緒／月末振込 など）
4. 会計処理は何を使っているか（弥生・freee・マネーフォワード・税理士へ紙 など）
5. インボイス（適格請求書登録番号）の記録が必要か

## 使い方

```
# ブラウザで直接開く
open keihi/index.html

# または公開サイトから
https://<ドメイン>/keihi/
```

初回は【設定】→「サンプル投入」で、データが入った状態の動きを確認できます。
